3. 熔断（Circuit Breaker）

3.1 什么是熔断

当下游服务（如数据库、RPC 服务）出现故障时，如果调用方继续疯狂请求，故障会像雪崩一样扩散。熔断器在检测到连续失败后，直接拒绝请求（快速失败），给下游喘息恢复的时间。

3.2 三种状态

  • Closed：正常调用
  • Open：直接拒绝所有请求（快速失败），经过冷却时间后进入半开
  • Half-Open：放少量请求探测，成功则恢复 Closed，失败则回到 Open

3.3 go-zero 中的熔断

go-zero 的熔断器基于 Google SRE 论文实现（core/breaker 包），特点是不需要配置阈值，自适应根据错误率计算是否熔断。

使用方式：自动生效，零配置！

  • 所有 RPC 客户端（zrpc）自动集成熔断
  • 所有 model 数据库查询自动集成熔断（sqlx 封装）
  • Redis 操作也有熔断保护

3.4 熔断与降载的关系

  • 熔断：保护下游（我失败了就不去打扰你了）
  • 降载：保护自己（负载太高了，丢一部分请求保命）

go-zero 的 API 服务在 MaxConns 超限时会自动返回降载响应（503）。

5. 链路追踪（分布式追踪）

微服务下一个请求要经过多个服务，出问题时无法定位是哪个服务慢。链路追踪记录每个请求在每个服务的耗时，形成一条完整调用链。

5.1 原理：TraceID 透传

每个服务通过 gRPC metadata / HTTP header 透传 TraceID，日志里带上 TraceID，就能把一次请求的所有日志串起来。
