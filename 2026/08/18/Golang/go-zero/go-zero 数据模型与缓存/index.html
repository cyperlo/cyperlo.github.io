3. 缓存机制原理（重点）

go-zero 的缓存方案非常巧妙，理解它对排查问题很有帮助。

3.1 缓存 key 设计

  • 主键缓存：cache:user:id:{id}
  • 唯一索引缓存：cache:user:username:{username}

3.2 缓存一致性策略：双写 + 删除

关键点：先更新数据库，再删缓存，而不是先删缓存再更新库，避免脏数据窗口。极端并发下仍可能有短暂不一致，可通过延迟双删等方案进一步优化（生产上一般可接受）。

3.3 缓存穿透与空值缓存

查询不存在的 id（如 FindOne(999999)）时：

  • 第一次：查库没有 → 不写缓存（返回 ErrNotFound）
  • 恶意刷不存在 id → 每次都穿透到数据库

解决方案：对不存在的 key 也缓存空值。go-zero 生成的缓存代码中已经处理了这一点，通过 CachedExecCtx / QueryRowCtx 等缓存执行器自动完成：

CachedQueryRowCtx 等是 go-zero 封装的缓存执行器，自动处理缓存读写、空值缓存、分布式锁（防止缓存击穿）。正常业务不需要手动操作 Redis 来维护这块缓存。

7. 常见问题

7.1 缓存与数据库不一致

先更新库再删缓存，仍存在极小窗口。生产方案：

  1. 延迟双删：更新库 → 删缓存 → 延迟 500ms → 再删一次
  2. 订阅 binlog（如 canal）异步删缓存
  3. 缓存设置短过期时间兜底

7.2 大量缓存同时过期（缓存雪崩）

  • 过期时间加随机偏移：AccessExpire + rand.Intn(60)
  • 多级缓存（本地缓存 + Redis）
