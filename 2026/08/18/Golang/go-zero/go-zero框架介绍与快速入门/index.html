go-zero 框架介绍与快速入门

官方文档：https://go-zero.dev/zh-cn/

1. 什么是 go-zero

go-zero 是一个集成了各种工程实践的web 和 rpc 框架，由好未来（学而思）开源（很多人误以为是字节跳动开源，这里澄清一下：go-zero 是好未来开源的项目），目前已是国内最流行的 Go 微服务框架之一，在 GitHub 上拥有 30k+ star。

go-zero 的设计哲学：简单、高效、稳定。它内置了非常多开箱即用的能力：

  • API 语法与代码生成（goctl）：通过一份 .api 文件即可生成完整可运行的 HTTP 服务代码
  • RPC 支持：基于 gRPC，内置 etcd 服务注册与发现
  • 服务治理：自适应限流、熔断、降载、超时控制
  • 链路追踪：内置 OpenTelemetry 支持
  • 中间件：JWT、CORS、日志、恢复等开箱即用
  • 数据层：内置 sqlx（对 database/sql 的封装）、Redis 客户端、缓存机制

2. 为什么选择 go-zero

对比其他 Go Web 框架（gin、echo）或微服务框架（go-micro、kratos），go-zero 的核心优势：

特性 gin/echo go-zero 说明
代码生成 无 goctl 一份 DSL 生成 API + RPC 全套代码
服务治理 需要自己集成 内置 限流、熔断、降载开箱即用
服务发现 无 etcd 微服务间自动注册与发现
数据库 自己写 sqlx + 缓存 内置缓存一致性方案
学习成本 低 中等 需要理解 DSL 语法
生产就绪度 一般 高 经过大规模生产验证

一句话总结：如果你要写的是单体 Web 应用，gin 足够；如果你要写微服务架构，go-zero 是当前 Go 生态里工程化最完整的选择。

5. 项目结构深度解析

goctl api new 生成的目录结构：

关键理解：各目录职责

  • types/：数据定义，由 .api 文件生成，一般不改
  • handler/：HTTP 层，负责参数解析、调用 logic、返回响应
  • logic/：业务层，纯业务逻辑，不关心 HTTP 细节
  • svc/：依赖注入，把 config、数据库、Redis 等统一放到 ServiceContext，供 logic 使用

典型的调用链：
HTTP 请求 → handler（解析参数）→ logic（业务处理）→ 返回 JSON

6. 读懂 greet.api 文件

这是 go-zero 的核心 DSL，打开 greet.api：

逐行解读：

  • type Request struct：请求结构体，path:"name" 表示参数来自 URL 路径
  • type Response struct：响应结构体，json:"message" 表示 JSON 序列化字段名
  • service greet-api：定义服务名
  • @handler GreetHandler：生成名为 GreetHandler 的 handler
  • get /from/:name：HTTP 方法 + 路由，:name 是路径参数

常用参数标签

标签 含义 示例
path 路径参数 Id int64 \path:”id”``
form 表单/Query 参数 Page int \form:”page,default=1”``
json JSON Body 参数 Name string \json:”name”``
header Header 参数 Token string \header:”Authorization”``
